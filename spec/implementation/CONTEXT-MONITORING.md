# Retained context-window monitoring

Status: normative implementation extension, not implemented behavior. Owner: M10. Audience: engineers implementing capture, accounting, retention and their clients. After reading, an implementer must be able to retain and inspect a scoped context history without mistaking classified output for observed model input. This contract extends existing children; it adds no child, module or DAG node. Source requirement IDs are allocated by SPEC and TRACEABILITY.

## Scope and ownership

Capture available user input, exposed system/developer input, thinking, tools and assistant content; preserve detailed history for later inspection. Prefer harness/provider structured evidence. Classify ambiguous captured text through the shared M12.4 `DecisionEngine`, with typed Choice answers and native confidence. [Decision engines](DECISION-ENGINES.md) is canonical for profiles, the shared `SystemOneAdapter`, transport, capabilities, model identity and resource admission. Code owns segmentation, counting, membership, thresholds and control flow; the classifier supplies labels only. No component recovers concealed instructions or hidden chain of thought.

Native capture defaults on. M07 freezes `context_monitoring.capture_enabled`, optional `context_monitoring.decision_profile_ref` (ID/version/digest), acceptance policy, question pack, bounded budget and resource policy; unconfigured new drafts leave the observer disabled. A selected profile supplies destination, authentication requirements, capability evidence and frozen model identity. Launch review shows the admitted sanitized content, destination, profile/model, native-confidence threshold, limits, deferred/overlap policy and missing readiness. Missing required credentials or capabilities disable classification with a visible reason; they never invalidate competitor readiness or trigger another provider. Schema-aware migration maps existing `typesafe | disabled` choices losslessly to an equivalent versioned TypeSafe profile or disabled state, preserving threshold/model/budget/destination/credential reference and original schema provenance. Historical raw response/analysis schemas and bytes remain readable and unchanged; migration never reclassifies captures.

## Identity, coverage and evidence

Every capture binds `run_uid`, `result_id`, full `TrialRef`, `task_id`, `invocation_id`, `session_id`, `agent_id`, optional `parent_agent_id`, `window_id` and, when known, `request_id`. A request can have several observation phases; a window spans requests until a native reset/compaction boundary. A subagent has its own identity/window even if it shares a process. Unknown native IDs receive scoped adapter-generated IDs labelled as synthetic; synthetic IDs establish local identity, never proof of input membership.

Use immutable `capture_id`, `entry_id`, `segment_id`, `snapshot_id` and source sequence/range. Retain adapter/harness/provider/model versions, timestamps and monotonic clock scope. A segment is a deterministic bounded block with sanitized source reference, digest, byte ranges, native tags and relevant neighbor references. Boundaries follow structured messages/blocks first and deterministic text framing second; never ask a classifier to invent boundaries. Render source text inert. Repeated bytes at different native positions are not necessarily duplicates.

Three independent provenance fields are mandatory:

| Field | Required meaning |
|---|---|
| `classification` | Native label/source/version and optional classifier annotation/analysis ID, selected effective label, disagreement and reason. A native role is not a decision-model prediction. |
| `count` | Integer or `null`, metric scope, method (`native_reported`, `exact_retokenized_input`, `estimated_text`, `unknown`), fidelity (`exact`, `estimated`, `unknown`), tokenizer/model/framing version, count basis (`original`, `redacted`, `native_counter`), coverage and source refs. |
| `membership` | `included | excluded | unknown`, snapshot/request/phase binding, native membership evidence and coverage. Classifying a log never proves it is in the current window. |

Coverage uses complete/partial/unknown plus covered/expected ranges, source availability and typed limitations. Unknown totals or category counts are `null`, never zero. A known zero requires evidence that the relevant complete scope contains none. Category omission and a missing source are explicit, including `not_exposed`, `not_captured`, `redacted`, `capture_gap`, `unknown_membership`, `tokenizer_unavailable`, `framing_unavailable`, `observer_disabled`, `observer_unavailable`, `observer_budget_exhausted` and `classification_pending`.

## Categories and token semantics

The fixed classification vocabulary and criteria are versioned together as `context-labels/1`:

| Label | Content assigned to this class |
|---|---|
| `system_input` | Exposed system/developer instructions and runtime metadata supplied as input; retain native subtype `system`, `developer` or `metadata` where known. Never infer hidden content from output. |
| `user_input` | User-origin input, including benchmark task/specification content delivered with that role. |
| `thinking` | Reasoning text actually exposed and identified as such; uncertain narrative is insufficient evidence of concealed reasoning. |
| `thinking_summary` | Explicitly exposed reasoning summary; never equivalent to underlying hidden reasoning. |
| `tool_definition` | Tool schemas/descriptions available to the target model. |
| `tool_call` | Invoked tool name/arguments and structured invocation content. |
| `tool_result` | Returned tool output, including errors. |
| `assistant_output` | Other assistant-origin text; later replay into input retains this origin label and separately records input membership. |
| `context_summary` | Compaction or conversation summary supplied in place of prior content. |
| `protocol` | Observable framing, separators, control records or other protocol content. Only native evidence determines whether it consumed target tokens. |
| `unclassified` | Ambiguous/mixed content, insufficient evidence or rejected classification. |

Tools may be displayed as one group but definitions/calls/results remain separate. Grouped system input retains exposed developer/metadata distinctions. Quoted role names inside a block do not change its outer origin. Unknown/unclassified blocks and unmapped or boundary-crossing tokens aggregate into `unattributed`, with separate reasons; they are not quietly reassigned to the closest category.

A **context snapshot** describes one model request/window phase's actual input membership. A **captured stream** describes observed content over time. **Billed usage** describes provider/harness request consumption. Keep separate DTO sections and charts for these scopes. Never sum all streamed text, all past request inputs, or cumulative billing to claim current context use. Generated output/reasoning is not necessarily in a subsequent input. Cache reads are generally overlapping input evidence, not an additional context category; use the native overlap semantics and count a token position once.

Retained **Gen tok/s** follows the matched request-generation timing and pooled-ratio contract in [benchmark statistics](BENCHMARK-STATISTICS.md); it is distinct from instantaneous advisory live rates and context occupancy. Observer calls contribute to neither competitor throughput nor competitor input/output totals.

Exact context partition requires the target model/version tokenizer and complete serialized input framing plus token-position/byte-span alignment, or equivalent native category/membership evidence. Merely counting each text chunk with a tokenizer does not establish additivity: concatenation and framing can change tokenization. When complete framing is available, tokenize the complete input once, map token positions to nonoverlapping segments, and leave crossing/unmapped positions unattributed. Store deduplicated token positions/ranges; no double count from overlapping captures. Do not persist credential-bearing token IDs.

With only text, retain a labelled text-token estimate and its tokenizer/basis; do not promote it to exact model-context accounting. Native-reported is a source method, not an exactness guarantee: retain documented counter semantics and mark rounded/estimated or unverified native readings accordingly. A provider-reported input total may be known while the category partition remains partial/unknown. An unexplained difference is a reconciliation discrepancy, not invented category usage. When native token positions establish a complete total but some positions cannot be mapped, those known positions may be counted as unattributed; arithmetic residuals alone cannot establish their identity or cause.

Native counters for opaque reasoning are retained only with their documented scope, overlap and phase. Output reasoning counters remain output usage unless native evidence separately establishes input membership. A reasoning summary's token count measures that summary. No estimated hidden instructions, guessed reasoning text or LLM-generated token counts are allowed.

Show percent used only when a native used-total and context limit describe the same target model, request/window and phase. Retain limit provenance and denominator; do not select an unrelated model catalog limit or divide an estimated text count by it. Category shares require a compatible total and matching membership/count basis, with partial coverage visible. Never force shares to 100% by allocating unknown residuals. A native over-limit reading remains an anomaly with its raw values, not silently clamped data.

Compaction, reset, dropped history and truncation append explicit transitions with previous/new window IDs and native cause/evidence. Retain original segments and snapshots; a compacted history is not deleted. Deduplicate stream retries by stable source identity/range, not text equality. Repeated input in separate requests remains separate request membership and billed traffic. Nested agents and windows are never pooled into a synthetic current context. Where native membership is unavailable, provide observed-history inspection and label the current-context breakdown unavailable.

## Durable capture and sealing

M05 produces sanitized structured observations and raw text blocks through the M10-owned `ContextCaptureSink`, separate from the lossy client event stream. Before redaction, code may derive counts from ephemeral original bytes/native token evidence; retain count-basis and redaction metadata. Sanitize before persistence or external submission. Retained sanitized text is not proof that the original token text or partition can be reconstructed exactly. Credential values never enter logs, classifier state, exported metadata or persisted token IDs; the shared adapter uses credentials only for the selected profile's configured authentication and never forwards a TypeSafe key to a local endpoint.

```python
class ContextCaptureSink(Protocol):
    async def accept(self, observation: ContextObservation) -> ContextCaptureReceipt: ...
    async def close(self, scope: ContextCaptureScope, cutoff: ContextCutoff,
                    operation_id: str) -> ContextClosureReceipt: ...
class ContextEvidenceRecorder(Protocol):  # M02 implements
    async def append_context_capture(self, result_id, bundle, operation_id) -> None: ...
    async def append_context_analysis(self, result_id, entry, operation_id) -> AnalysisEntryReceipt: ...
class ContextClassifier(Protocol):        # M10 bridge consumes shared DecisionEngine
    async def classify(self, batch: ContextQuestionBatch) -> ContextDecisionBatch: ...
```

`ContextCaptureReceipt={schema_version:1,capture_id,entry_id,payload_digest}` acknowledges durable journal/spool acceptance. Identical IDs/digests retry idempotently; conflicting bytes/scope fail. `ContextClosureReceipt={schema_version:1,scope,source_digest,cutoff,segment_count,snapshot_count,gaps,status,operation_id}` binds all accepted source entries and gaps; scope includes result/trial/invocation identity. Digest canonicalization follows the shared credential-free canonical JSON/SHA-256 contract, excluding receipt bookkeeping. `status` is `complete | partial | unavailable | off`; off/unavailable are explicit envelopes, not empty complete capture.

M05's stream reader never awaits the classifier. It uses bounded memory and disk spooling, with a supervised capture worker acknowledging durable entries. Proposed engineering defaults: 8 MiB RAM and 256 MiB spool per invocation, bounded entry size 64 KiB, and a separate reserved control journal for gaps/closure. Full queues/spools produce typed dropped source-range gaps rather than blocking on classifier throughput or dropping evidence silently. Capture I/O can affect resource use and timing; disclose that limitation. If even the gap/closure receipt cannot be persisted, finalization remains pending with a typed storage error.

M11 joins producers; M05 closes every capture source; M10 `drain_run` awaits source closure, acknowledged capture work and persisted gap records, then includes context capture bundles/closure receipts in its existing finalization inputs. M02 attachments, source digests and closure envelopes must be durable before its measurement receipt and seal. This extends the existing barrier; it does not replace M18 closure. Classifier completion is never part of the execution sealing barrier. Stop/recovery follows the same partial-data path and cannot invent a source tail, rerun a competitor or reopen sealed facts.

M02 adds a versioned `context_capture` execution-evidence envelope and evidence kinds for segments, snapshots, transitions and gaps. The `context_capture/1` format capability is bound to the frozen launch/capture protocol; new launches require both capability and envelope, including off/unavailable capture, while pre-protocol records retain their original bytes/digests. These immutable source digests belong in `facts_digest`. Legacy records without the envelope read as unavailable (`not_captured_legacy`), not zero or corruption. A live unsealed envelope may be pending with no closure receipt; seal and sealed-record import require a durable closure and final explicit status for every declared source. New required capture envelopes cannot be omitted to bypass receipt checks. Every raw evidence record passes normal result/trial binding and M17 integrity validation.

## Shared decision observer bridge

M10.2 implements `ContextClassifier` in `adapters/decision_context.py` as a consumer of M12.4's `DecisionEngine`; the observer is separate from competitors and graders. Both a remote TypeSafe profile and a directly addressed compatible local Ollama profile use the shared `SystemOneAdapter` and `/v1/systemone` contract. Authentication, limits, capabilities, status handling, native usage/confidence semantics and model identity are profile/dialect data governed by [decision engines](DECISION-ENGINES.md#one-system-one-transport-explicit-dialects), not a second HTTP implementation here. Selecting an endpoint alone never proves compatibility or local execution.

Adopt one typed Choice question per ambiguous block against bounded sanitized state containing `blocks`, each with `segment_id`, text and permitted source metadata. Criteria are keyed by exactly the eleven labels above. Instructions identify the actual `segment_id`, require classification of only that block, treat block text as evidence rather than instructions, and forbid inferred hidden content. Embedding the segment ID in a question-map key alone cannot identify the target to the model. Questions evaluate independently against fixed state; code composes decisions. The bridge binds source digests, profile and question-pack references to a `DecisionRequest` with purpose `context_classification`. ([TypeSafe API](https://docs.typesafe.ai/api), [State](https://docs.typesafe.ai/concepts/state).)

Persist requested and resolved model identity and their evidence with every analysis/call. TypeSafe requires a pinned versioned model; an unexpected resolved version is invalid/unclassified with `observer_model_mismatch`. For local profiles, a response model-name echo is not proof of executed weights: retain the frozen discovery/artifact binding, runtime/quantization and identity uncertainty according to the shared contract, and block a changed binding pending a new profile version. Initial context packs admit sanitized text only; do not silently OCR, transcribe or invoke another model for nontext content. Enforce both pack and selected-profile payload/context limits; capability mismatch remains explicit. ([TypeSafe models](https://docs.typesafe.ai/models), [Ollama API](https://docs.ollama.com/api/systemone).)

The runtime validates the dialect response and returns typed `ChoiceDecision` results with sanitized raw answers, native distributions/confidence, usage, deficiencies and `DecisionCall` receipts. M10 retains the complete distribution and acceptance reason, not just a winner. Exact expected answer IDs/types/criterion keys, finite bounded probabilities/confidence, compatible usage and consistent winning choice are mandatory. Sum and tie tolerances come from the frozen versioned profile/dialect policy and are retained with the call; no universal `1e-6` rule applies across engines. Malformed/missing/extra answers, inconsistent winners, ties or unsupported confidence semantics become unclassified with reasons. Never silently renormalize probabilities, synthesize confidence or replace one engine's confidence formula with another's.

Initial label acceptance requires the explicit `native_confidence` policy and valid native Choice probabilities/confidence. Accept a label only at or above the threshold frozen per profile/question pack. The provisional project threshold is `0.8`, requiring held-out evaluation by model/pack version; it is not a provider recommendation, classification-accuracy estimate or guarantee. Low/unknown confidence and abstention remain unclassified. Confidence statistics from different engines are not pooled as calibrated correctness. No automatic extra LLM fallback is permitted. ([TypeSafe confidence](https://docs.typesafe.ai/confidence).)

Native structured labels take precedence. The bridge normally handles only ambiguous text; an explicit audit/reclassification may include native-labelled blocks. Retain native and predicted labels plus disagreements in every case; never replace native evidence. An invalid/low-confidence classifier result cannot erase a native label. Classification changes neither token counts nor membership evidence. A strong prediction still leaves unknown context membership unknown.

M10 freezes bounded batch construction and a per-run observer budget; M12.4 consumes that budget atomically for every dispatch/retry and applies profile/runtime concurrency, queue, byte, timeout and retry limits. Effective worker limits may adapt within frozen ceilings; the bridge owns no second worker/retry layer. Proposed consumer defaults remain at most 8 questions and 16 KiB sanitized state per batch, 32 KiB total encoded request, 1,000 attempts and 8 MiB outbound payload per run, and 10 minutes total observer request time, all subordinate to stricter profile limits. These are project controls, not provider capacity claims. Oversize blocks are deterministically split with source ranges or marked unclassified; never silently truncate. Uncertain fit, provider failure, queue saturation and budget exhaustion preserve captured evidence with pending/deferred or typed unavailable/unclassified reasons. Optional monetary caps require retained price evidence; otherwise cost remains unknown.

Local inference defaults to deferred execution through M11's `DecisionResourceLease` until no managed competitor measured window is active across any run. The lease covers warmup/model load, inference and resource settlement; M10 capture, native counts and snapshots continue while classification is pending. Explicit frozen `live_local_overlap` permits disclosed overlap; remote classification may run asynchronously within its bounds. Unknown routing uses conservative admission. Cancellation, bounded drain, unknown server activity, restart reconciliation and clean measurement admission follow the shared resource contract; a transport disconnect does not prove inference stopped. No observer decision changes competitor control flow or context.

`ContextObserverAccount` records have role `context_observer` and bind analysis/scope, `DecisionCallId` and attempt/observation references, profile/model, timestamps, usage, retries/queue state and known cost through the runtime's auxiliary-accounting port. M10 owns this consumer ledger; the shared runtime owns durable call receipts. A decision call is not an M05 harness invocation and never enters `InvocationObservationSink` or competitor `UsageReported` facts. Observer charges stay separate from grading and competitor token usage, cost, latency, throughput and rankings. Known local API charge zero does not establish zero host energy or operating cost. Disclose capture/transport/classifier CPU/memory/network overhead, residency and overlapping work intervals; never subtract guessed observer energy from whole-machine M18 readings. The observer cannot call back into the competitor, alter its context or send it decisions.

## Append-only analysis and offline behavior

M02 stores analysis sidecars at `analyses/context/<result_id>/<analysis_id>/`, outside sealed `results/`. Each analysis binds source digest/ranges, selected segment IDs, classifier/question-pack/tokenizer/config versions, frozen decision profile/version/digest and capability evidence, redaction policy, requested/resolved model identity, acceptance/resource policy, threshold, trigger, budget and `DecisionCallId` receipt references. `analysis_id` identifies one immutable selection policy/configuration. A live analysis fixes invocation/capture scope at creation; accepted ranges may grow until its final closure cutoff. An explicit reclassification pins a closed source digest/range selection that cannot grow. Append immutable attempt, decision and terminal entries with stable entry IDs/digests; derive status (`pending | running | complete | partial | failed | cancelled | disabled | unavailable`) by folding that ledger. No mutation of sealed evidence, counts or facts is permitted.

Source capture may continue while live classification runs: each batch pins the committed source-entry digests it uses; final analysis settlement names its complete selected source digest/cutoff. New source ranges require additional immutable entries. A later explicit reclassification creates a new analysis ID; it never rewrites a prior analysis. Restart may reconcile an already authorized pending observer job within its frozen budget; an uncertain in-flight attempt is recorded and any retry consumes remaining budget. Imported/offline records never resume observer work automatically.

Report/ZIP acquisition pins the raw source digest plus an optional analysis ID, ledger cutoff/digest and status, including `pending`, `partial` or no analysis. Later annotations cannot silently enter an already pinned artifact. This extension adds capture evidence to `facts_digest` while preserving all existing sealed fact inputs and excluding classifier annotations; `payload_digest` additionally covers the selected analysis snapshot and observer-account evidence. M17 includes these files in its integrity manifest and validates scopes/source links through M02's codec. Same-result-ID imports with differing snapshots remain conflicts, never implicit analysis merges. Retention/report/export readiness does not wait for classifier completion. Reading, rendering, exporting and importing make no model calls.

The portable mapping is fixed. For each result, M02 exports a canonical JSON descriptor at `results/<result_id>/evidence/context/analysis-selection.json`, schema `axbenchmark-context-analysis-selection/1`, with `result_id` and a `selections` array sorted by `capture_id`. Each entry is `{capture_id, source_digest, analysis: null | {analysis_id, through_entry_id, ledger_digest, status, files}}`; `files` lists relative path, SHA-256 and size for the selected analysis/observer-account closure. Every retained capture appears once; `analysis: null` explicitly selects native-only evidence. A `context_capture/1` package requires this descriptor even when every selection is null. This supports separate analyses for multiple tasks/invocations instead of silently choosing one result-wide analysis. Query-level `AnalysisSelection` still selects one analysis for its already scoped target.

Selected sidecar files are packaged only at `results/<result_id>/evidence/context/analyses/<analysis_id>/…`, through M02 pinned openers. The descriptor's file paths are confined beneath that analysis directory, references must close over its exact selected ledger cutoff, and the M17 inventory covers descriptor and files. The descriptor and selected bytes enter `payload_digest`; neither alters `record.yaml`, sealed source facts or `facts_digest`. M17's exclusion of unrelated outside-result files remains, with only this explicitly leased, validated sidecar mapping allowed. On import, M02's existing `read_incoming(staged_result_dir, staged_run_dir)` finds the descriptor beneath the staged result, validates IDs/source/cutoff/digests, and registers sidecars at local `analyses/context/<result_id>/<analysis_id>/` under the same publication marker. It never installs those sidecars as mutable execution evidence or automatically resumes observer jobs. Missing/extra/escaping references fail; genuine pre-protocol packages without a descriptor remain native/unavailable legacy records.

M13 places the scoped context tables, timelines and analysis provenance inside the existing `TASK_EVIDENCE` report part. Extend its pinned `ReportSnapshot` with the same per-capture selections and prepared context projections; no new `ReportPart` enum is required. Include a labelled unavailable/native-only state when no selected classification exists. Only the selected immutable cutoff enters the self-contained HTML; later decisions cannot alter it.

Only the live latest-snapshot projection may coalesce; durable history/gaps/closure/analysis ledger entries cannot depend on it. Extend M11 live/run routes explicitly in the registry; no inferred topic names.

HarnessLive exposes an Open context detail route with its resolved task/trial/session/agent/window. Switching selections cancels/discards stale responses and old subscription generations. Unknown values show “not exposed” or their actual reason, not an empty chart or zero bar.

JSON includes all provenance; human output preserves explicit scope, unknown/partial states and observer costs. Resolve human run labels through existing M02 rules only.

M13 includes scoped context history/partition only where evidence permits, with source availability, capture gaps, native/classified distinction, threshold/model, counts/membership provenance and pinned analysis status. ## Acceptance and integration gates

Fixture tests are deterministic and never require a live decision-server call. They are required additions to the owning children's suites; no claim of classifier accuracy follows from synthetic API fixtures.

1. **Conservation and nonadditivity:** a complete native framed input has each token position assigned exactly once to a class or unattributed; boundary-crossing tokens stay unattributed.
