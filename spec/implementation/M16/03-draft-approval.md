## Draft and canonical contracts

`planning.create_manual(benchmark_type, project_type, target_inspection_id, inputs, evaluation_profile_refs, idempotency_key) -> JobRef -> DraftDTO` runs durable import/capture/validate/persist stages. Consume the reviewed M16.1 inspection and frozen current-folder capture, exact authored prompt or explicitly ordered provided specs, and approved/authored evaluation profiles. No installed harness, model, readiness verification, planner session or catalog adapter is required; no model call supplies missing content. Capture remains an internal job stage, not a new public capture namespace.

Persist inputs/order, idempotency binding, operation stages and terminal outcome independently of the transient job cache. The same key/request resolves one operation/draft; conflicting reuse fails. Disconnect does not cancel the engine job. Startup exposes interrupted operations as failures without silently repeating capture or planning; partial inputs/captures never become an approvable draft. Explicit retry follows M16.1 source-token checks; complete approved captures never refresh from the source path.

Persist exact original/current file bytes and optional generated bytes, name, definition format, benchmark/project type, shared refs, ordered tasks, checks/support, services/dependencies/protocol/rubric and profile refs, completed baseline/capture binding, source status, origin, optional planner/session, selected task, optimistic version and operation status. `DraftOrigin` is `one_shot | provided_specs | planned | revision | duplicate`; new manual origins have no planner/session/invocation ids and cannot regenerate. Merely opening/rendering strict UTF-8 text never normalizes its bytes or emits an edit.

Implement all parent DraftEdit variants, including M01-validated SetName, exact-byte task/shared-file edits, AddSpec/ReplaceSpec/ReorderSpecs/RemoveSpec and service/check edits. Mutations require `base_version`, preserve original-byte provenance and increment version. One shot has exactly T1 and no shared specification; provided multi-step has at least two unique primary files in reviewed order, one per task. Invalid/missing/unreadable/duplicate/non-UTF-8 inputs fail visibly. Removing below the minimum leaves an explicitly incomplete draft or is refused; it never changes type automatically. A benchmark-type change is explicit, validates/clears incompatible content visibly and invokes no planner.

Reopen manual/planned drafts at shared review with the saved task; active/failed manual operations reopen capture progress/failure, never the planner picker. Revision/duplicate drafts reopen the saved task editor and preserve source format. Review labels imported/original bytes accurately; reset-to-generated requires actual generated bytes. Regeneration is an explicit eligible planned multi-step action only, with version-checked validated replacement and outside-scope edits preserved. Approved drafts are read-only and excluded from unfinished rows.

Explicit recapture of an open draft requires `base_version` and reviewed M16.1 inspection/policy tokens; retain the prior complete snapshot until success. SourceChanged, active recapture or mismatched inspection/capture/version binding blocks approval with changed facts. An unchanged completed capture can be approved without rereading a disappeared source; later explicit inspection detecting changes requires recapture/review. Refreshing approved work first opens a new revision, never mutates its packaged bytes.

Checks preserve the full M08 requirement/phase/observation/failure-rule contract and declared support closure; incomplete edit rows remain explicit approval issues. Validate M12 rubric profile/applicability and web screenshot-inspection requirement from M12 requirement_for(rubric) and M08 final-regression capture declarations, never supply silent defaults.

## Versioned canonical conversion

`definition_input` is pure and dispatches the selected version; application `to_frozen` calls the sole M01 `DefinitionCodec.write(input, files)`, then reads back through that codec. New manual and newly planned drafts use `axbenchmark-definition/2`. Legacy revision/duplicate seeds retain v1, its original approved definition/baseline and ordinary edit semantics until an explicit upgrade; never auto-upgrade/relabel/rehash approved v1. Preserve v1 reader/writer/reference closure, manifest bytes and golden hashes. A legacy one-task v1 definition remains visibly legacy multi-step, not one shot.

V2 requires `benchmark_type`, `project_type`, sorted unique `shared_specifications` (existing `specification` payload role), ordered `tasks[{task_id,prompt_path,check_ids}]` (existing `task_prompt` role), and `baseline:{kind:empty|folder,files:[{path,executable}]}`. Empty requires `[]`; folder requires nonempty admitted files under `baseline/`. One-shot stores its exact prompt once at T1 with empty shared refs; multi-step stores one primary per ordered task. The whole specification view is derived from shared plus ordered primary files once, never a second serialized index or duplicate prompt.

The remaining required `acceptance_checks`, `execution_protocol`, `services`, `rubric` and `dependencies` remain complete, including support closure and explicit empty arrays/documents only where owning validators allow. No planner omission permits missing fields or invented defaults. Use exact defining bytes and semantic executable flags. Exclude plan.json, edit history, display name/task titles, source path/commit/time, planner selection, costs and saved configurations from the payload.

Return FrozenDraft(display: DisplayMetadata, payload: CanonicalPayload); M01 computes manifest/digest. Renaming name/title alone changes display metadata, not identity; mode, task order, exact defining text/protocol/rubric/checks, baseline bytes and executable flags do. V1-to-v2 conversion changes identity even with equivalent content; the outer manifest/ZIP need not change version.

## Approval and publication

PreviewApproval returns version, digest, issues/check flags and verdict after source/active-operation guards. Command receives base_version, inspects the same version under the shared mutation lock and rechecks completeness, capture/inspection/version binding and identity before publication; stale tokens/versions are refused and duplicate identity is blocked, including a display-only rename.

DraftStore exports seed/inspect/prepare_approved(tx, draft_id, version, sha)/commit_view(tx)/rollback(tx, token) exactly as M01 consumes. `inspect(draft_id) -> DraftApprovalInput(version, frozen: FrozenDraft, capture_binding)` captures the approval input atomically; seed preserves source definition/baseline for revision/duplicate editing.

prepare_approved stages expected version, approved marker and optional approved planner provenance together, returning a token. Manual origins stage no planner provenance. commit_view is durable readiness only. All reads—including PlannerRecord and unfinished—resolve the captured PublicationView.

M16 coordinates manual/planned approval through public RevisionRegistry/DraftStore/PublicationTransactions: prepare revision/lineage plus this participant, acknowledge both and publish one marker. No private adapter/store access or independent commit is allowed. M01's revision/duplicate coordinator additionally prepares M07 copies only after the user's copy choice.

Copied configurations get new IDs and new SHA pin through M07; source configurations/results remain untouched. No participant emits an approval/config/revision event during prepare or commit_view.

Before-marker failure rolls back only token-owned changes; pre-existing same-content storage is never deleted. After-marker failure rolls forward cleanup/outbox and returns/reconciles the same committed identity on response loss.

A journal retains transaction/draft/version/SHA and cleanup state. Recovery completes rollback or roll-forward before readers enter; unresolved rollback stays hidden with an actionable error, never half approval.

Discard refuses running work/approved drafts; confirmed discard removes only M16-owned unfinished state. PlannerRecord returns the explicit selection only for published planned provenance; drafts/imports without that record return None.

## Board/data boundary

Serve M01 manual NewTemplate, typed manual progress/failure and shared PlanReview/Reopened/Services/Edit/ServiceEdit/Approve/ApproveIdentical plus LibraryDrafts/Revise flows. Regenerate is present only when eligible. DTOs expose exact-byte references, mode/order/capture/profile issues and engine-derived capabilities; manual progress never claims LLM planning. GetDraftTask returns task id, same-task checks and engine snapshot_label; T4 maps to after T4 in both review states and one-shot T1 is its final competitor stage. UI widgets do not inspect source files or compute identity/capture validity.
