# M12.2 — judging-worker

Parent: [M12 worker and ports](../reference/modules/12-quality-judging.md#1-engine-component). Requirements: R035, R046, R067, R077, R082–R084, R134, R139, R144, R150, R153–R154. Findings: F03, F06, F09, F13; shared F02/F04/F15/F18.

Outcome: durable original/additional review work with globally sequential automated assessments and independent human cases through `harness_review`, `decision_rubric` or `human_review`, protected artifacts, separate accounting and complete terminal dispositions. This is proposed implementation work under the binding [decision-engine contract](../DECISION-ENGINES.md).

Use fakes for isolated orchestration, then real providers at the gate. M11.4 requires this child, so do not require completed M11.4 here.

## Exact lifecycle interfaces

```python
class RunJudging(Protocol):
    async def judge_run(self, run_uid: RunUid) -> BatchId: ...
    async def wait(self, batch_id: BatchId) -> OriginalJudgingSettlement: ...
    async def stop(self, batch_id: BatchId, cause: TerminalCause) -> OriginalJudgingSettlement: ...
    async def recover(self, run_uid: RunUid, cause: TerminalCause) -> OriginalJudgingSettlement | HumanRecoveryPending: ...
    async def batch_for_run(self, run_uid: RunUid) -> BatchId | None: ...
```

Settlement is `{settlement_id, run_uid, batch_id?, roster_digest, dispositions, settlement_digest, cleanup, settled_at}`. Each expected ResultId/TrialRef has exactly one durable disposition with outcome, optional committed review ID/digest, required failure/not-judged reason and optional invalidation ID. No queued/reviewing/pending-write state counts as settled.

`judge_run` requires all execution results sealed, current identity and M11 admission eligibility; create/return one original batch by RunUid/full frozen roster. Include missing-artifact trials and unusable judge as explicit NOT_JUDGED; never omit a result to satisfy the barrier.

`wait` reads durable completion, independent of missed events. `stop` closes admission before cancelling and returns only durable dispositions/cleanup or typed settlement-pending error. Repeated calls return the first settlement; later stop causes stay M11 lifecycle data.

`recover` never invokes a grading model through either backend, including after a cold restart; an observer resume policy cannot resume grading. Resolve prior committed reviews and immutable prepared intents; settle unfinished queued/reviewing automated slots NOT_JUDGED(cause), using engine_lost for startup loss and the supplied stopped/identity_invalidated cause for those terminal paths. For automated selections with no batch, reconstruct the complete roster from M02 and settle every original without creating assessment work. Persisted human drafts/awaiting cases follow M12.5 recovery, not this automated interruption rule. Retry returns the same settlement or durable HumanRecoveryPending restoration as applicable. Explicit stopped/identity_invalidated recovery settles unfinished human cases; engine_lost alone preserves sealed pending human work. The durable originals/<run_uid>.yaml index supports batch_id=None; M11 retains the complete dispositions through M02 TerminalRetention.

M11 uses judge_run→wait normally, stop for existing batches, recover for engine loss or terminal paths before batch creation. Pass settlement to M02 finish_run_retention; storage errors leave readiness pending. A later explicit rejudge creates ADDITIONAL work and cannot reopen original retention.

## Worker and persistence

One FIFO engine worker serializes automated assessments across both model backends, runs and rejudge jobs. Human admission prepares durable cases and releases that slot; awaiting human input is not an active automated assessment. Each delivered ResultId/TrialRef gets one assessment. `GradingEngine.assess(immutable_input, plan)` dispatches the frozen backend strategy; harness assessments use a new invocation/conversation and decision assessments use bounded stateless shared System One calls. Neither backend receives earlier assessment state, answers, reviews or history.

Both automated strategies and the human form consume the same M12.1 immutable anonymous projection of delivered source/tests/documentation, approved specification/tasks, frozen rubric and M08 behavioral evidence. Keep alias-to-ResultId/TrialRef mappings outside requests; recursively exclude competitor identity, all performance/cost/time/hardware measurements, Gen tok/s, input/cached/output/reasoning tokens, measured Files / LOC, weights/rankings and other reviews, including nested metadata. Admitted source/test/documentation artifacts remain available despite withholding their measured statistics. Automated UI assessment requires verified `image_input` and actual final-regression images under the pinned profile: web retains 1440×1000 and 390×844; native mobile uses its approved target/state capture matrix. Other profiles require only their declared evidence/modalities. Ordered image bytes bind to admitted IDs/digests; exclude per-task/historical screenshots. No repairs, new acceptance checks, OCR or textual image substitutes.

For `harness_review` only, use M05 `JudgingScope(review_id, result_id, trial, artifact_label)` and standard InvocationRequest with Role.judge. Each assessment receives its own read-only artifact/input copy and scratch area. Require the parent's typed `EnvironmentSpec.judge` extension for delivered SnapshotRef/protected roots/scratch; fail before invocation if protection cannot be established. Never substitute a fresh baseline or writable competitor workspace.

For `decision_rubric`, `decision_grader.py` constructs bounded requests from M12.1's deterministic `DecisionRubricPack`, preserving the approved rubric. Freeze profile/version/digest, model/capability evidence, pack/question-format, evidence-selection, batching/composition/mapping digests and acceptance/resource policies in the assessment plan and JudgeGroup. Retain manifest inclusion/exclusion/coverage; required evidence cannot be silently truncated or summarized to fit. Missing required scope or context overflow yields explicit input/coverage deficiencies. Mandatory Choice grades have exactly nine labels: `1`, `1.5`, `2`, `2.5`, `3`, `3.5`, `4`, `4.5`, `5`; parse exact half-steps and never round a Score expectation. Accepted coverage, concrete criterion/reason, admitted evidence-support, all three substantive comment axes (code quality, usability/developer experience, specification) and limitation decisions must satisfy the unchanged parent/M12.1 validation. Missing/rejected/low-confidence/contradictory decisions remain deficiencies. Code composes rationale/comments with `code_composed_from_decisions` and question/answer/anchor/evidence provenance; harness prose remains `model_authored`. Boilerplate cannot complete a review.

`CheckJudge` validates the selected backend's actual frozen capabilities and readiness independently of harness/observer availability. Missing, incompatible or unready decision profiles disable start/rejudge with a typed reason and setup entry; an explicit request returns typed unusable before dispatch, without automatic fallback. Unknown screenshot support is unusable; text-only Jev cannot grade UI. Metadata/profile reads invoke no model; explicit bounded probes belong to M12.4.

M12.4 alone acquires M11's shared `DecisionResourceLease` for dispatch; the worker never nested-acquires it. Default local/unknown-routing calls defer until no managed competitor measured window is active across any run, even after this run seals. Wait through the shared bounded, fair, cancellable queue without holding a run lock needed to finish measurement; the lease covers warmup through inference/resource settlement. Explicit overlap policy remains frozen and observable.

Allocate stable assessment/reserved Review IDs and freeze the actual JudgeGroup route/profile/model/effort/treatment. Await `ResultRecorder.open_judge_assessment(rid, identity, operation_id)` before either automated backend dispatches. Pass assessment/group IDs through call, route and accounting envelopes; retain exposed usage even before a Review exists. After drainage, publish a graded/ungraded Review linked by the unique assessment/reserved ID, or a failed/not_judged disposition without a Review. Original human cases stay on their separate prepared-intent flow. Canonical group digests include selected semantic refs/digests, never derived binding/owner/receipt/publication IDs that would create a hash cycle. Allocate/persist stable batch/review/assessment IDs before dispatch. Persist a harness InvocationId only for `harness_review`; decision slots retain distinct DecisionCallId references to M12.4's durable intents/receipts, never fake InvocationId, PID, conversation or process transcript. Capture/pass a shared PublicationView on M01/M02 reads, close revision leases, validate artifact/evidence/trial bindings and check identity before/after assessment. M08 PhaseNotReady/missing artifact is explicit input unavailability, not a fabricated review. Never retry an ambiguously dispatched grading call as if it had not run.

For harness work, drain M05 response/usage and await `JudgingCostAccounting.measure(invocation_id)` with stable observation IDs. For decision work, await durable runtime call receipts and M10's auxiliary `JudgingCost.record_decision(receipt)` path keyed by DecisionCallId/observation ID. Include partial stopped/failed use and unknown cost; retain grading separately from context-observer accounts and all competitor measurements, including Gen/input/output/Files/LOC statistics. Known local API charge zero does not establish known host operating cost.

Persist full immutable prepared Review bytes/digest, then call M02 add_review. Identical lost-ack retry uses review ID/digest; conflict fails. M02 appends review-owned raw response/input/evidence/cost atomically; do not call execution attach_evidence after seal. Publish review.finished only after durable acknowledgement.

Crash after preparation may replay that exact append without regrading or invoking. Crash before a complete prepared intent never grades partial output. Keep diagnostic response/evidence, raw typed decisions/receipts and available cost with not-judged reason; recover does not interpret process exit or HTTP success as quality.

Explicit RUN judging.stop delegates to M11 runs.stop; M11 calls internal RunJudging.stop without recursive dispatch. Close admission, cancel/drain/join the active slot, retain completed reviews, settle remaining originals and let terminal/report waits finish. Harness cleanup uses M05 process-tree/protection semantics; decision cleanup uses M12.4 transport drain, durable call receipts and resource-lease settlement. Bounded drain that cannot prove server termination retains `server_state_unknown` and typed cleanup/resource limitations; clean measurement admission remains gated until independent readiness resolves activity unless frozen overlap policy permits contaminated work. Never claim clean process cleanup or kill an externally owned decision server. Do not kill the global FIFO worker for other batches.

REJUDGE is a separate cancellable job; its JobRef/batch ID addresses only additional work. Check M02 artifact/can_rejudge, current identity and chosen capability; freeze a new selection/group preserving backend, profile/version/digest, requested/resolved model, runtime/quantization and rubric/pack/mapping/evidence/acceptance fingerprint. Keep original review/group unchanged; different fingerprints remain separate groups with separate cost. Import/view/profile queries and reweighting invoke no judge. Serialize cancellation versus review preparation/commit through the shared job/lifecycle gate; cancellation cannot be reported while a grade later commits, and an already committed review retains its actual job outcome.

Catch every IdentityMismatch before ordinary input/invocation/validation errors. Await M11 invalidate(run_uid, check, detected_at, source) for durable registration only, then unwind the reporting worker. Supervisor cleanup joins afterward; never self-join. Identity applies to the retained artifact's original RunUid even for additional rejudging.

Serialize admission/review commit against M11 stop/invalidation; completed reviews survive the overlay and all original-run results become non-comparable. Remaining dispositions may cite NOT_JUDGED(identity_invalidated) only after overlay durability. Persistence failure outranks a false completed claim.

**Frozen domain contract.** CheckJudge/ReviewNext resolve the frozen family/rubric/evidence plan and validate domain-specific completeness before machine invocation or human case admission. Backend/API recovery, native matrix/build/lifecycle, DevOps observation modes, product-agent case modes and supplied-brief/document relationships remain read-only admitted evidence. No judge invokes an app/device/tool/deployment/evaluation/validator. Harness and decision results plus human submissions use M12.1 validation; all three retain identical coverage gaps and immutable rubric refs. Rejudge uses retained approved evidence in a separate group and cannot reopen verification.

**Committed review mapping.** The validated harness/decision/human union maps through M02 to normalized JudgeGroup, raw half-step grade/comment/evidence/deficiency/limitation and disposition rows. Full immutable role/profile/form-policy/rubric refs remain queryable; raw response/decision envelopes remain evidence files. Human drafts, sessions and immutable pending intents are M12 working state and can stay file-backed. Only M02 receipt-backed finalized reviews feed Q; M12 supplies no competing score or committed review store.

**Route, comparison and profile interfaces.** Resolve and freeze only the explicitly selected harness-review access/existing profile via M04; revalidate immutable source/executable/assets/route qualification before each fresh judge session. ## Human admission and submission settlement

[M12.5](05-human-review-web.md) is a completed provider prerequisite. M12.2 calls `GradingEngine.prepare_human(HumanBatchPlan) -> AwaitingHuman` / `HumanReviewHost.prepare` for a frozen human selection; it never waits for the browser inside automated `assess`. A pending case has no terminal `ReviewOutcome` or fake NOT_JUDGED disposition. Keep the run in `judging` with `wait_reason=human_input`, preserve sealed execution facts, and permit unrelated automated work. `RunJudging.wait` remains pending until all originals have real durable dispositions.

Implement `HumanSubmissionSink` through the existing shared validation, immutable prepared-review intent and M02 idempotent append/disposition barrier. A graded submission, explicit ungraded deficiency or skip can settle a case; drafts, browser closure and opener failures cannot. Replay exact acknowledged/prepared intents with the same ReviewId/digest after response loss. Serialize submission against stop/invalidation; completed reviews survive, unfinished cases are revoked and settled only through the corresponding explicit lifecycle cause. Human input wait, browser activity and any self-reported effort never enter competitor statistics; there is no inference dispatch or fabricated call receipt.

Persisted human DRAFT/AWAITING cases recover as `HumanRecoveryPending` without auto-opening a browser, regrading or abandoning drafts. SUBMITTING replays only immutable prepared intent through the existing append barrier. Return pending refs promptly to M11, which keeps human activity/status rather than demanding terminal settlement. Completed human reviews remain read-only; explicit rejudge creates additional work and cannot reopen original retention. Add all-profile/partial-form/skip/open-failure/restart, duplicate-submit/stale-version/stop-race, no-model-call and automated-queue-release integration gates from M12.5.
