# M02.2 — retention-services

Parent: [M02](../reference/modules/02-retained-results-comparability.md#1-engine-component). Requirements: R015, R035, R066, R067, R076–R081, R114, R116, R117, R122–R124, R134, R140, R142, R147, R153–R155. Findings: F02, F03, F06, F09, F14; consume F07 currency rules.

Outcome: durable scoped facts and evidence, receipt-backed sealing, atomic import participation, and `results.*` queries with reliable readiness. Proposed work; fake-provider success is not end-to-end acceptance.

## Authoritative SQLite retention — R191

Start with an empty database; do not implement migration of old filesystem records or a compatibility fallback. Large evidence stays in `fs_evidence`, with durable digest-checked references. This is an extension of M02.2, not a new implementation node.

Query snapshots pin that transaction's published view; direct read-only SQL observes the same atomic collection. Seals, human submissions and operation retries commit their dependent rows together. Analysis persistence is append-only derived data and never edits a sealed fact or original review.
