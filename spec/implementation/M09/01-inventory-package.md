## Concrete contract

`build_package(authoring_bytes, source_files) -> (CanonicalPayload, DisplayMetadata)` parses safe YAML, validates the authoring shape, and calls `DefinitionCodec.write(DefinitionInput, Sequence[PayloadFile])` exactly once before identity computation.

Supply every M01 field: format, frontend project type, specification, ordered tasks/check ids, suite/support paths, protocol, services, rubric/web profile, dependencies, and `baseline: {kind: empty, files: []}`. No implicit defaults or baseline directory entry.

Services/dependencies are explicit empty declarations in their owners' schemas. Protocol names `index.html` as future workspace output and declares fresh sessions/project prefix/commit-per-task. It must not reference a nonexistent packaged app.

`template.yaml`, `about.yaml`, display name/description/task titles/label and provenance stay outside `CanonicalPayload`. Defining prompt/check/rubric text is never normalized. All seven check support files listed in the parent are closed over by `support_paths` with role `acceptance_checks`.

Use the parent's exact 30-row catalog and order. Each task's descriptor `check_ids` equals its suite rows. Validate unique ids, required observations, phase targets and support references with M08's published reader; no “at least one check” substitute.

`PackageContents` carries M01's decoded canonical definition and separate display material. Runtime `LoadBuiltins` reads generated bytes with `DefinitionCodec.read`, then delegates `identity_of(payload)` to M01. Never regenerate/rewrite a corrupt released descriptor.

`DefaultPin` records key/order, expected digest, preserved-input digests, catalog mapping and rubric weights outside defining payload. Fixture pins are test-only. At release, freeze the completed real payload and retain r1 forever when r2 is added.

`check_default_contract` returns all inspectable violations with paths. Invalid JSON/closure yields a visible diagnostic registration with unavailable fields, not a fabricated hash, hidden package or runnable/default candidate.

`DescribeContract` and `DescribeCoverage` derive requirements/counts/phases from the parsed suite. Return 30 unique, 30 at-task, 30 final, 19 final-artifact and 11 final-history; legacy `also_checked` is empty. About text cannot assert additional checks.

`RelationToDefault` uses M01 identity/lineage. A same-name six-task copy is a look-alike; an older valid built-in is neither the current default nor a look-alike. `choose_default` and results-based upgrade behavior stay M01-owned.
